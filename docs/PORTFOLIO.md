# VeilNote 프로젝트 포트폴리오

## 1. 한 줄 소개

VeilNote는 회의 음성과 민감한 원문을 기기 안에서 처리하고, 비식별화된 토큰만 AI에 전달해 회의 요약과 실행 업무를 만드는 개인정보 보호형 회의 에이전트입니다.

## 2. 프로젝트 정보

| 항목 | 내용 |
| --- | --- |
| 프로젝트 | VeilNote |
| 팀 | TRACEGATE |
| 행사 | 코드게이트 AI 스타트업 해커톤 |
| 트랙 | 업무·생산성 자동화 / 회의록 정리 / 협업도구 |
| 개발 형태 | 해커톤 프로토타입 |
| 나의 역할 | 백엔드 중심 개발, API 계약, LLM 연동, 프런트엔드 연결 |
| 핵심 설계 | 원문·매핑 테이블은 브라우저에 보관하고 서버에는 토큰만 전송 |

## 3. 문제 정의

AI 회의록은 편리하지만 실제 기업 회의에는 고객명, 회사명, 연락처, 계약 금액처럼 외부 서비스에 그대로 전달하기 어려운 정보가 섞여 있습니다. 기존 방식처럼 음성이나 원문 전체를 서버로 보내면 보안팀의 승인을 받기 어렵고, 사용자는 어떤 정보가 외부로 나가는지 직접 통제하기 어렵습니다.

VeilNote는 “AI가 원문을 보지 않아도 회의 내용을 구조화할 수 있는가?”를 핵심 질문으로 삼았습니다.

## 4. 해결 방식

1. 브라우저의 Whisper가 음성을 텍스트로 변환합니다.
2. 규칙, 사용자 사전, 온디바이스 NER가 개인정보와 업무상 민감정보를 탐지합니다.
3. 사용자가 탐지 결과를 확인하고 누락·오탐을 수정합니다.
4. 원문을 `[PERSON_1]`, `[ORG_1]`, `[MONEY_1]` 같은 토큰으로 치환합니다.
5. 전송 직전 매핑의 원래 값이 본문에 남아 있는지 역방향으로 검사합니다.
6. 검사에 통과한 토큰화 본문만 백엔드와 LLM에 보냅니다.
7. 백엔드는 구조화된 요약·결정사항·액션아이템을 반환합니다.
8. 브라우저가 로컬 매핑 테이블을 사용해 화면 표시 직전에 결과를 복원합니다.

## 5. 시스템 구조

```text
[브라우저: 신뢰 영역]
마이크/텍스트
  -> 온디바이스 Whisper
  -> 규칙 + 사전 + NER 탐지
  -> 사람의 확인
  -> 토큰화
  -> 잔존 개인정보 검사
  -> 매핑 테이블은 로컬에 유지
           |
           | 토큰화 텍스트만 전송
           v
[백엔드]
입력 검증
  -> 서버 측 잔존 PII 게이트
  -> LLM 프록시
  -> 구조화 JSON 응답
           |
           v
[브라우저]
로컬 복원
  -> 회의 요약
  -> 결정사항
  -> 담당자·우선순위·마감 근거가 포함된 업무
```

## 6. 담당 업무

### 6-1. 백엔드

- 토큰화 회의문을 받는 REST API의 요청·응답 계약을 정의했습니다.
- LLM API 키가 브라우저에 노출되지 않도록 서버 프록시 구조를 구성했습니다.
- 한 번의 LLM 호출로 요약, 결정사항, 액션아이템을 함께 생성하는 구조화 출력 계약을 설계했습니다.
- 토큰화되지 않은 이메일, 전화번호, 주민등록번호, 카드번호를 탐지하면 LLM 호출 전 `422`로 차단하도록 보안 게이트를 정의했습니다.
- 유효성 오류, 업무 없음, 잔존 개인정보, LLM 실패를 `400`, `404`, `422`, `502`로 구분해 프런트가 상황별 안내를 할 수 있게 했습니다.
- 회의에서 생성된 업무를 목록·단건 조회, 수정, 삭제할 수 있는 v2 업무 API 계약을 작성했습니다.
- 서버가 회의 원문과 요청·응답 본문을 로그에 남기지 않는 정책을 문서화했습니다.

### 6-2. 프런트엔드 연결

- 프런트가 보낼 필드와 백엔드 응답 필드를 맞추고 `fetch` 요청을 결과 화면에 연결했습니다.
- `422` 차단과 일반 API 실패를 구분해 사용자에게 재확인 또는 재시도 동작을 안내하도록 했습니다.
- 서버 응답의 토큰을 브라우저의 매핑 테이블로 복원해 팀 요약과 개인 성과 문장을 렌더링하도록 연결했습니다.
- 받아쓰기 결과가 탐지, 사람 검토, 토큰화, 유출검사, API 요청으로 끊김 없이 이어지도록 데이터 흐름을 맞췄습니다.
- 브라우저와 서버에서 같은 탐지·토큰화·유출검사 규칙을 사용할 수 있도록 공용 ESM 모듈 경로를 설계했습니다.

## 9. 핵심 기술 판단

### 원문과 매핑을 서버에 보내지 않기

비식별화가 형식적인 마스킹에 그치지 않도록 매핑 테이블 자체를 브라우저 밖으로 내보내지 않았습니다. 서버는 토큰의 의미를 알 수 없고, 복원은 화면 표시 직전에만 일어납니다.

### 사람의 확인을 파이프라인에 넣기

NER과 정규식만으로 모든 민감정보를 정확히 잡는 것은 불가능합니다. 따라서 자동 탐지 결과를 사용자가 확정하는 Human-in-the-Loop 단계를 필수 흐름으로 넣었습니다.

### 전송 전 역방향 검사

탐지 목록만 신뢰하지 않고, 매핑 테이블의 원래 값들이 토큰화 결과에 남아 있는지 다시 대조합니다. 하나라도 남으면 요청을 보내지 않습니다.

### LLM 호출 한 번으로 제한

해커톤 시간과 데모 안정성을 고려해 필수 LLM 호출을 한 번으로 묶고, 요약·결정사항·업무를 구조화된 JSON으로 받도록 했습니다.

### 날짜는 상대일수로 처리

LLM이 절대 날짜와 요일을 직접 계산하면 오류가 생길 수 있으므로 `dueOffsetDays`만 받고, 실제 날짜는 회의 시작 시각을 기준으로 브라우저가 계산하도록 설계했습니다.

## 11. 기술적으로 어려웠던 지점

### 브라우저에서 음성 처리

마이크의 샘플레이트가 Whisper 입력과 다를 수 있어 PCM을 16kHz 모노로 리샘플링했습니다. 발화 뒤 무음 구간을 기준으로 오디오를 나누고, 추론 요청은 큐로 직렬화해 워커에 한 번에 하나씩 전달했습니다.

### UI 스레드 보호

Whisper 추론을 Web Worker로 분리하고 PCM 수집은 AudioWorklet에서 처리해, 무거운 추론 중에도 화면이 멈추지 않도록 구성했습니다.

### 보안과 사용성의 균형

자동 탐지만 강제하면 오탐 때문에 사용성이 떨어지고, 사용자 확인만 믿으면 누락 위험이 큽니다. 자동 탐지, 사람 확인, 역방향 검사, 서버 게이트를 단계별로 쌓아 서로의 약점을 보완했습니다.

### 프런트와 백엔드 계약 변화

프로토타입은 `/api/process`와 `teamSummary`·`personalStar` 응답을 사용하고, v2는 `/api/process-meeting`과 `summary`·`decisions`·`tasks`를 사용합니다. 실제 통합 저장소에서는 버전 경로 또는 어댑터를 두어 계약 변경을 명시적으로 관리해야 합니다.

## 12. 포트폴리오용 성과 문장

### 이력서 한 줄

- 코드게이트 AI 스타트업 해커톤에서 VeilNote의 백엔드와 프런트엔드 연동을 담당해, 브라우저에서 비식별화한 회의문만 LLM에 전달하고 구조화 결과를 로컬에서 복원하는 보안 중심 AI 파이프라인을 구현했습니다.

### 이력서 상세형

- 토큰화 회의문을 처리하는 REST API와 LLM 프록시를 설계하고 프런트엔드 `fetch` 흐름을 연결했습니다.
- 잔존 개인정보를 `422`로 차단하는 이중 유출 방지 정책과 요청·응답 무로그 원칙을 정의했습니다.
- Web Worker·AudioWorklet 기반 온디바이스 Whisper 결과가 개인정보 탐지, 사람 검토, 토큰화, API 호출, 로컬 복원까지 이어지도록 통합했습니다.
- 단일 LLM 호출에서 요약·결정사항·액션아이템을 구조화해 반환하는 v2 API 계약과 업무 CRUD 명세를 작성했습니다.

### 30초 면접 답변

“VeilNote는 민감한 회의 원문을 AI 서버에 보내지 않는 회의 에이전트입니다. 저는 백엔드와 프런트 연동을 맡았습니다. 브라우저에서 원문을 토큰화하고 매핑은 로컬에 남긴 뒤, 백엔드는 토큰화 텍스트만 받아 LLM을 호출하도록 계약을 설계했습니다. 전송 전후에 잔존 개인정보를 검사하고 `422`로 차단했으며, 응답은 브라우저에서만 복원했습니다. 기능보다 데이터 경계를 먼저 정하고 양쪽 구현을 맞춘 경험이 핵심입니다.”
